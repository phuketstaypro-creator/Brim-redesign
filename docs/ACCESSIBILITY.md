# Доступность

## Статус

Цель frontend — WCAG 2.2 AA. Это цель проверки, а не заявление о достигнутом соответствии.

`package.json` предоставляет `npm run test:a11y` на базе Playwright/axe, но автоматический scanner покрывает только часть требований. Ручные проверки screen reader, keyboard, zoom, reflow, cognitive clarity и доступности документов должны быть выполнены отдельно на финальном deployment.

Текущие PDF/документы отсутствуют, поэтому их доступность не проверена. CMS content и будущие редакционные материалы также могут ухудшить результат независимо от качества шаблона.

## Контентный контракт

При интеграции CMS редактор обязан:

- сохранять логичную иерархию заголовков без выбора уровня ради размера;
- заполнять содержательный `coverAlt` для информативной фотографии;
- оставлять пустой alt только у действительно декоративного изображения;
- не дублировать подпись дословно в alt без необходимости;
- писать осмысленный текст ссылки вместо «сюда» или полного URL;
- указывать язык фрагмента, если он отличается от русского;
- использовать списки и таблицы семантически;
- не передавать смысл только цветом, положением или формой карточки;
- добавлять captions/transcript для будущих аудио и видео;
- проверять каждый загружаемый документ отдельно.

В текущих `site.assets` и `newsItems` есть alt-поля, но их точность должна быть подтверждена вместе с самими изображениями и правами на них.

## Обязательные автоматические проверки

```bash
npm ci
npm run build
npm run test
npm run test:e2e
npm run test:a11y
```

Перед релизом сохранить версию браузера/axe и результаты. Целевое условие для axe: 0 critical и 0 serious violations на согласованном наборе страниц и состояний. Нулевой результат axe не равен полной сертификации.

Покрыть минимум:

- `/`;
- `/education/`;
- `/news/` и одну news article;
- `/documents/`;
- `/sveden/` и один обязательный subsection;
- `/privacy/`;
- `404.html`;
- открытые menu, search и accessibility dialog states.

## Keyboard checklist

1. Начать с обновления страницы, не используя мышь.
2. Проверить видимость и работу skip link.
3. Пройти Tab/Shift+Tab через utility navigation, header, main и footer.
4. Убедиться, что порядок фокуса совпадает с визуальным и DOM-порядком.
5. Открыть/закрыть mobile menu клавишами Enter/Space и Escape.
6. Открыть search/accessibility dialogs, проверить начальный фокус, focus containment, Escape и возврат фокуса на trigger.
7. Проверить все controls и ссылки на различимость focus indicator.
8. Убедиться, что скрытая панель не получает фокус.
9. Проверить отсутствие keyboard trap.

Результат документируется по браузеру, ОС и устройству ввода. Исправление только mouse behavior не закрывает keyboard defect.

## Screen reader checklist

Минимум один Windows screen reader (например, NVDA) и VoiceOver на доступной Apple-платформе:

- корректный русский язык документа;
- понятный title каждой страницы;
- один `h1` и логичная heading outline;
- landmarks header/nav/main/footer;
- breadcrumbs с текущим элементом;
- доступные имена menu/search/accessibility controls;
- объявления открытого/закрытого состояния;
- понятный порядок news cards;
- дата новости читается как дата, а не декоративный набор;
- изображения имеют ожидаемый alt;
- сообщения поиска объявляются без потери фокуса;
- 404 явно называется страницей, которой нет.

Версию assistive technology и найденные ограничения сохранить в отчёте.

## Reflow, zoom и responsive

Проверить ширины:

```text
320, 360, 390, 768, 1024, 1440, 1920 px
```

Отдельно проверить browser zoom 200% и 400%. Критерии:

- нет горизонтального scrolling для основного текста и controls;
- header/menu не перекрывают содержимое;
- focus не скрывается за sticky elements;
- текст не обрезается;
- buttons и links не накладываются;
- новостная композиция остаётся читаемой и сохраняет естественный DOM-order;
- portrait/landscape/standard/featured cards не создают layout shift;
- content доступен при отключённых изображениях;
- размеры touch targets проверены вручную.

## Настройки отображения

Frontend предусматривает size, theme, images, spacing и motion preferences с локальным хранением. Для каждого режима проверить:

- фактическое визуальное изменение, а не только состояние кнопки;
- `aria-pressed` выбранного значения;
- читаемость текста и controls;
- сохранение после reload;
- доступный reset;
- корректную работу без localStorage;
- отсутствие обязательной анимации при reduced motion или motion off.

LocalStorage настройки интерфейса не доказывает правовое или accessibility соответствие само по себе.

## Цвет и motion

- Проверить contrast обычной, monochrome и high-contrast схем инструментом и вручную.
- Проверить text over image во всех реальных crop variants.
- Focus indicator должен быть виден на тёмном и светлом фоне.
- Не полагаться только на hover.
- `prefers-reduced-motion` и ручное отключение motion должны исключать несущественные transitions/animations.

## Документы

Каждый PDF/скан проходит отдельную проверку: text layer, теги, порядок чтения, заголовки, язык, таблицы, alt, bookmarks и контраст. Если исходный документ недоступен, нужна доступная HTML-альтернатива либо документированный план remediation владельцем контента.

Frontend-тесты не могут автоматически сделать загруженный CMS PDF доступным.

## Приёмочный отчёт

Для релиза сохранить:

- commit SHA и deployment URL;
- список проверенных маршрутов/states;
- axe output;
- screenshots 390/1440;
- keyboard checklist;
- screen reader/OS/browser versions;
- zoom/reflow results;
- список исключений и владельца каждого исправления;
- отдельный статус документов и CMS content.

Без этих результатов следует писать «подготовлено с учётом доступности», а не «полностью соответствует WCAG».

# БРХК — CMS-независимый редизайн

Статически генерируемый фронтенд Бурятского республиканского хореографического колледжа. Сборка создаёт отдельный наполненный HTML-документ для каждого публичного маршрута; JavaScript используется только для интерактивных улучшений интерфейса.

Проект не содержит CMS, административной панели или backend форм. Текущие данные в `src/data/` — интеграционный слой с частичным prototype/source-linked наполнением до получения проверенного экспорта действующей CMS колледжа.

## Текущий статус контента

- Все шесть записей в `src/data/news.mjs` имеют `contentStatus: 'source-linked'` и ссылку на действующий сайт БРХК. Полные тексты, авторы и вложения не перенесены; четыре записи пока ссылаются на корень официального сайта, а не на подтверждённый permalink статьи.
- Маршруты демонстрационного редизайна `/news/<slug>/` временно сохранены, хотя заголовки теперь связаны с публикациями действующего сайта. Окончательные URL и redirects определяются после CMS export и legacy inventory.
- `/privacy/` и `/consent/` содержат рабочие шаблоны, а не утверждённые локальные акты.
- Названия документов перечислены для демонстрации структуры; файлы, реквизиты и проверенные ссылки не получены.
- Обязательные подразделы `/sveden/` присутствуют как маршруты, но их фактические сведения и документы ещё не импортированы.
- Домен `brim-redesign.vercel.app` используется сборкой как staging base URL. Основной canonical-домен заказчиком не подтверждён.
- Исходник сцены `assets/stage.b64` невосстановим и не публикуется. Пока интерфейс использует только технически восстановленное фото учебного зала и его детерминированные portrait/square/landscape crops.
- Авторство, лицензии, согласия на публикацию и полные метаданные медиаматериалов не подтверждены.

До официального запуска `public/robots.txt` оставляет индексацию закрытой.

## Требования

- Node.js 24 рекомендуется файлом `.nvmrc`;
- допустимый диапазон в `package.json`: Node.js `>=22 <25`;
- npm с поддержкой lockfile v3.

## Локальный запуск

```bash
npm ci
npm run dev
```

Доступные команды:

```bash
npm run build       # генерирует dist/
npm run test        # сборка и структурные проверки HTML
npm run test:e2e    # браузерные сценарии Playwright
npm run test:a11y   # автоматическая проверка axe в Playwright
```

Build-скрипт очищает только корневую папку `dist/`, проверяет обязательные локальные изображения, создаёт 36 наполненных HTML-маршрутов, `404.html`, `sitemap.xml`, `rss.xml`, `search-index.json` и хешированные CSS/JS assets. `dist/` является воспроизводимым артефактом и не редактируется вручную.

## Структура

```text
build.mjs                 генератор статической сборки
public/                   копируемые без преобразования публичные файлы
src/data/                 CMS-независимые модели текущего контента
src/templates/            HTML-шаблоны страниц и компонентов
src/styles/               визуальная система и редакционная сетка
src/client/               меню, поиск и настройки доступности
scripts/                  локальный сервер и служебные команды
tests/                    структурные, браузерные и a11y-проверки
docs/                     документация передачи и интеграции
dist/                     локальный результат npm run build
```

Основные источники контента:

- `src/data/site.mjs` — общие метаданные, навигация, контакты и главная;
- `src/data/pages.mjs` — обычные страницы и обязательные `/sveden/`-шаблоны;
- `src/data/programs.mjs` — две основные и две дополнительные программы;
- `src/data/news.mjs` — source-linked новостные карточки и временные frontend-маршруты;
- `src/data/sveden.mjs` — перечень 14 обязательных подразделов.

ШКИ и «Балет для всех» остаются внутри образовательной архитектуры. Блок «Новые проекты» в проект не входит.

## Deployment

`vercel.json` запускает `npm run build` и публикует только `dist/`, без SPA rewrite и без загрузки исходников с raw GitHub в браузере. Push в `main` сам по себе не является доказательством deployment: после него необходимо проверить deployment ID, HTTP-ответы и фактический production HTML.
